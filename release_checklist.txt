NothingElse Release: CI required fixes & verification checklist

Purpose: items you must verify or provide in repository Secrets so GitHub Actions can produce a signed Release APK.

1) Required repository Secrets (exact names)
- KEYSTORE_BASE64
  - Description: base64 encoding of the keystore file (keystore.jks).
  - How to create locally: base64 -w0 signing/keystore.jks > keystore.jks.base64
  - Note: store the base64 string value as the secret KEYSTORE_BASE64 (no newlines).

- KEYSTORE_PASSWORD
  - Description: keystore store password (storepass).

- KEY_ALIAS
  - Description: alias inside the keystore used to sign the APK (e.g. "nothingelsekey").

- KEY_PASSWORD
  - Description: private key password (keypass) for KEY_ALIAS.

2) Quick verification commands (run on a trusted machine where you have the keystore and the secrets)
- Validate keystore locally:
  keytool -list -v -keystore signing/keystore.jks -storepass <KEYSTORE_PASSWORD>
  Expected: alias "nothingelsekey" appears, Entry type PrivateKeyEntry.

- Compute SHA256 of keystore (for integrity check):
  sha256sum signing/keystore.jks

- Create base64 of keystore (for Secret value):
  base64 -w0 signing/keystore.jks > keystore.jks.base64
  Then copy the single-line contents of keystore.jks.base64 to the GitHub Secret KEYSTORE_BASE64.

3) Workflow-side notes (what I changed & what to check in workflow)
- The workflow decodes KEYSTORE_BASE64 to signing/keystore.jks on runner.
- It expects secrets: KEYSTORE_BASE64, KEYSTORE_PASSWORD, KEY_ALIAS, KEY_PASSWORD to be present.
- I added a validation step that fails early if any of those secrets are missing.
- Confirm the workflow has lines setting KEYSTORE_FILE to ${{ github.workspace }}/signing/keystore.jks and exports KEYSTORE_PASSWORD / KEY_ALIAS / KEY_PASSWORD into GITHUB_ENV.

4) Common failure modes and fixes
- Failure: SigningConfig missing required property "storeFile"
  - Cause: KEYSTORE_BASE64 not set or decoding step skipped/failed, so signing/keystore.jks does not exist on runner.
  - Fix: ensure KEYSTORE_BASE64 is present and correctly base64-encoded; verify workflow step decodes it and file exists (the workflow already echoes "Keystore written to signing/keystore.jks").

- Failure: storepass or keypass incorrect
  - Cause: KEYSTORE_PASSWORD or KEY_PASSWORD wrong.
  - Fix: confirm passwords with local keytool check (see commands above) and update Secrets accordingly.

- Failure: KEY_ALIAS not found in keystore
  - Cause: alias mismatch between metadata and keystore.
  - Fix: run keytool -list to get actual alias; update the KEY_ALIAS secret to that value.
